## 2. DATA SCHEMA + EXAMPLES

**IMPORTANT:** There is **no SFT dataset** and **no record type with a `gold_cited_ids` field.**
The only record collections that exist are (a) the 27 **audit traces** and (b) the 5,349
**capture-scoring rows**. The audit traces store the **model's** citation
(`parsed_evidence_tokens`), not a gold citation. "Gold" token IDs are not stored on
disk — they are recomputed at scoring time inside `score_phase0_with_f1.py` via
`localize_gold()`. So the request for "a record with `gold_cited_ids`" cannot be
satisfied verbatim; the closest analogue is mapped below.

### Schema A — audit trace record (`phase0_f1_results.jsonl`, n=27)

| field | type | meaning |
|---|---|---|
| `case_id` | str | e.g. `img4_caseA`; suffix A/B/C/D = clean/noisy/masked/OOD |
| `image_path` | str | absolute path to the image shown |
| `question` | str | question asked |
| `gold_answer` | str | DocVQA gold answer string (text, not IDs) |
| `teacher_raw_response` | str | raw Sonnet 4.6 XML output |
| `parsed_evidence_tokens` | list[int] | **model's** cited token IDs (NOT gold) |
| `parsed_answer` | str | parsed `<answer>` text |
| `answer_correct` | int (0/1) | ANLS≥0.5 vs gold (or `"unanswerable"` match on refusal cases) |
| `evidence_valid` | int (0/1) | all cited IDs ∈ OCR menu (computed at original run time) |
| `format_valid` | int (0/1) | all 5 XML tags present |
| `refusal_appropriate` | int (0/1) | refused iff refusal expected |
| `expected_behavior` | str | `"answer correctly with cited tokens"` or `"refuse with empty tokens"` |
| `actual_behavior` | str | human-readable summary |

## 4. REWARD FUNCTION

**Location:** `phase0/pipeline.py:694-784` (`compute_evidence_reward`). Spec:
`phase0/REWARD_DESIGN.md`. Constants: `ABSTAIN_CREDIT = +0.4`, `FABRICATION_PENALTY = -0.5`
(`pipeline.py:690-691`).

**What it ACTUALLY computes (evidence component only):**

| regime | condition | value |
|---|---|---|
| refusal-expected, refused | `is_answerable=False`, `cited=∅` | **+1.0** |
| refusal-expected, over-cited | `is_answerable=False`, `cited≠∅` | **0.0** |
| answerable, honest abstain | `is_answerable=True`, `cited=∅` | **+0.4** (`ABSTAIN_CREDIT`) |
| answerable, fabrication | `is_answerable=True`, any cited ∉ valid_ids | **-0.5** (`FABRICATION_PENALTY`) |
| answerable, all valid | F1 of `cited` vs `gold_cited_ids` | **2PR/(P+R)** |
| answerable, all valid, gold=∅ | localizer placed no gold | **0.0** (P=R=0) |

Verbatim core (`pipeline.py:753-784`):
```python
    cited = set(cited_ids)
    gold  = set(gold_cited_ids)

    # Refusal-expected branches
    if not is_answerable:
        reward = 1.0 if not cited else 0.0
        return {"evidence_reward": reward, "evidence_precision": None, "evidence_recall": None}

    # Answerable: honest abstain
    if not cited:
        return {"evidence_reward": ABSTAIN_CREDIT, "evidence_precision": None, "evidence_recall": None}

    # Answerable: fabrication (strictly below ABSTAIN_CREDIT by construction)
    if not cited.issubset(valid_ids):
        return {"evidence_reward": FABRICATION_PENALTY, "evidence_precision": None, "evidence_recall": None}

    # Answerable + all cited valid: F1 set-overlap branch
    if not gold:
        return {"evidence_reward": 0.0, "evidence_precision": 0.0, "evidence_recall": 0.0}

    intersection = cited & gold
    precision = len(intersection) / len(cited)
    recall    = len(intersection) / len(gold)
    f1 = 2 * precision * recall / (precision + recall) if (precision + recall) > 0 else 0.0
    return {"evidence_reward": round(f1,4), "evidence_precision": round(precision,4), "evidence_recall": round(recall,4)}
```

**Divergences from `REWARD_DESIGN.md`:**
1. **The composite reward is NOT implemented.** `REWARD_DESIGN.md` §2 specifies a 4-component
   weighted reward (Answer 0.50 / Evidence 0.25 / Format 0.10 / Refusal 0.15). **Only the
   Evidence component (0.25) exists in code.** `answer_correct`, `format_valid`, and
   `refusal_appropriate` are computed as separate 0/1 flags in `pipeline.py`/`phase05.py`, but
   **nothing in the codebase combines them into the weighted 0.50/0.25/0.10/0.15 composite.**
   The "0.850 > 0.700 > 0.475" ordering in the doc is a hand-worked table, not produced by code.
2. **`evidence_text` text-matching:** described as dropped in `REWARD_DESIGN.md` §5; correctly
   **absent** from code. (Consistent.)
3. **`img1_caseB` scoring claim is contradicted by the data** — see §6, item 1.

**Tests:** `phase0/test_reward.py` — 25 unit tests covering `parse_response` and

## LOCALIZER QUALITY CHECK

**Method:** read-only. Ran the real `find_bbox` / `find_bbox_lenient` over a
**stratified sample of 100 CLEAN DocVQA validation images**, excluding
`handwritten` + `Image/Photo` (4,932 eligible of 5,349). Proportional stratification
by first `question_type`, deterministic stride. No augmentation, no masking — clean
images only. Tesseract 5.5.1 (same engine as the audit). Per-image OCR was obtained
by piping the PNG to `tesseract stdin stdout tsv` (see §ENV note below) and applying
the **exact** `extract_ocr_tokens` filter (word rows, `conf >= 0`, dense IDs). Script:
`/tmp/localizer_check.py` (outside the repo; nothing in the repo was modified).

### 1. Gold localizer — matching logic (verbatim)

`localize_gold` (`score_phase0_with_f1.py:58-61`) is the entry point; it delegates to
`find_bbox` then `find_bbox_lenient`:
```python
def localize_gold(tokens: list[dict], gold: str) -> set[int]:
    bbox = find_bbox(tokens, gold, 0.85) or find_bbox_lenient(tokens, gold)
    return set(bbox["token_ids"]) if bbox else set()
```
`find_bbox` (`phase05.py:120-139`) — the core fuzzy sliding-window match:
```python
def find_bbox(tokens, gold, threshold=0.85):
    if not tokens or not gold.strip(): return None
    words = [t["word"] for t in tokens]
    n = len(gold.strip().split())
    best_score, best_start, best_n = 0.0, 0, n
    for wn in range(max(1, n - 1), n + 2):
        for i in range(len(words) - wn + 1):
            window = " ".join(words[i: i + wn])
            s = difflib.SequenceMatcher(None, window.lower(), gold.lower()).ratio()
            if s > best_score: best_score, best_start, best_n = s, i, wn
    if best_score < threshold: return None
    matched = tokens[best_start: best_start + best_n]
    return { "x1": ..., "score": best_score, "token_ids": [t["id"] for t in matched] }
```
`find_bbox_lenient` (`phase05.py:142-166`) — cascading thresholds + numeric fallback:
```python
def find_bbox_lenient(tokens, gold):
    for thr in [0.85, 0.7, 0.6, 0.5]:
        b = find_bbox(tokens, gold, thr)
        if b: return b
    numeric = re.sub(r"[^\d.]", "", gold)         # currency/number fallback
    if numeric and numeric != gold:
        for thr in [0.85, 0.7, 0.6]:
            b = find_bbox(tokens, numeric, thr)
            if b: return b
    return None
```
Character-level `SequenceMatcher.ratio()`, case-insensitive, window sizes `n-1..n+1`.
(The audit pipeline's `find_answer_bbox`, `pipeline.py:211-266`, is the identical algorithm.)
**As-coded, `localize_gold` matches against ONE gold string** (`rec["gold_answer"]` = the
first answer); it does not iterate DocVQA's alternate gold spellings.

### 2. CITATION INTERFACE — what the model's menu contains

Each OCR menu line is **`id`, `word`, AND `bbox`** — bounding boxes are in the prompt.
`tokens_to_str` (`pipeline.py:202-206`, dup in `phase05.py:93-97`):
```python
def tokens_to_str(tokens):
    return "\n".join(
        f"{t['id']}\t{t['word']}\t{t['x1']},{t['y1']},{t['x2']},{t['y2']}"
        for t in tokens)
```
Injected as `f"OCR tokens:\n{token_str}\n\nQuestion: {question}"`
(`pipeline.py:411`, `_build_user_content:466`; `phase05.py:314`). The system prompt
declares the format: *"a numbered OCR word list, each line formatted as
`<id>\t<word>\t<x1,y1,x2,y2>`"* (`pipeline.py:381`).

**Interpretation:** the model **sees** `(id, word, bbox)` for every token, but the
**citation unit is the ID only** — `<evidence_tokens>` is a JSON list of integer IDs, and
the reward checks **ID set membership / F1**, never bbox. So bounding boxes are *provided as
spatial context* but are **not** part of the citation target and **not** scored. A
clean-image SFT record needs `(id, word, bbox)` in the prompt and an **ID list** as the
citation label; bbox coordinates are not required in the label.

### 5. Fixable formatting vs genuine OCR miss (sizes the natural abstain class)

Test: re-match each failure under **aggressive normalization** (lowercase, strip all
non-alphanumeric). If the gold then matches OCR ≥0.85, the text **is present** and the
failure is a fixable formatting issue; otherwise it is a genuine miss.

- **Fixable formatting (currency/date normalization): 0 / 11.**
- **Genuine OCR miss (text absent from OCR output): 11 / 11.**

residual failures are **genuine** — the gold value simply is not in Tesseract's output
(table cells, figure axes, garbled scans; best windows are page-footer Bates URLs or
unrelated cells). **Adding more text normalization would recover ≈0 of these.** They are a
true abstain population.

### ENV note — pytesseract is broken *in this sandbox only* (not a Tesseract problem)

`pytesseract.image_to_data(...)` raises `UnicodeDecodeError` here, even on a known-good
audit PNG. Root cause is **not** Tesseract and **not** the user's environment: under this
tool's execution sandbox, files written to `/tmp/claude-*` are **not readable by child
processes** (Leptonica: *"image file not found"*). `pytesseract` always round-trips the
image through such a temp file, gets a non-zero return, then fails decoding Tesseract's
(binary-containing) stderr. Direct `tesseract` on a project-dir path returns rc=0 fine, and
the 5,349-row capture cache was produced successfully — so **pytesseract works in the user's
normal (non-sandboxed) runs.** Workaround used here: pipe the PNG via **stdin**
(`tesseract stdin stdout tsv`), avoiding temp files. **No Tesseract reinstall/reconfig was
done or is needed.** Action item is only relevant if Phase-1 code is ever run under the same
sandbox: prefer stdin piping or write temp images into the project dir.
