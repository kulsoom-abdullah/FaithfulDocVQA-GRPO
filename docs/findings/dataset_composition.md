## Abstain composition + Tesseract failure analysis (2026-06-28)

_Working-log entry. CPU-only analysis over the val gen files (ck-1284 + 6-checkpoint pooled)._

**Abstains are pure OCR-miss.** Every abstain = "gold answer present but not recoverable from the frozen Tesseract OCR menu" — never a missing/ambiguous gold. Code path (`scripts/build_master_dataset.py`): `localize_all_variants()` runs the imported bbox localizer over all gold variants → `localized = bool(cited)`; the record then sets `target_is_abstain = (not localized)` and `abstain_reason = None if localized else "ocr_miss"` (build asserts `target_is_abstain == (not gold_localized)`). So `abstain_reason == "ocr_miss"` for all 436 abstains.

**Doc-type skew** (see the VALIDATION / ALL tables above — not duplicated): figure/diagram is **~5× over-represented** among abstains — **31.2%** abstain rate vs **6.1%** val overall, and **32.6% (15/46)** of the val abstains despite being only ~6% of val records. Full dataset: figure/diagram **20.8%** abstain rate vs 8.8% overall.

**found_answer accuracy on abstains, by doc_type** (did the MODEL read what OCR missed?):
- **Non-figure abstains: 30/31 = 0.968** (ck-1284; table/list 14/14, layout 12/12, free_text 2/2, form 2/3) → "OCR missed it, the model read it fine" — the clean faithfulness case.
- **figure/diagram abstains: 60/90 = 0.667** pooled across all 6 checkpoints (ck-1284: 9/15 = 0.600; per-checkpoint range 0.60–0.73) → **~1/3 of figure abstains the MODEL also can't read.**
- Answerable side confirms it: figure/diagram is the model's **worst** doc_type for found_answer — **0.848** vs **0.91–0.94** for table/list/layout/form. (n=15 figure abstains is small, ±~13 pp, but the across-checkpoint spread is tight.)

**Conclusion — do NOT grow abstain coverage by mining figures.** The figure/diagram abstain class is **partly confounded**: ~1/3 are *vision*-hard (the model can't read them either), so they don't cleanly isolate the "read-but-not-citable" behavior we want to train. To expand abstain data, **manufacture clean abstains from model-readable types (table/layout/form) by removing the gold token(s) from the OCR menu** — that yields "model reads it, can't cite it" without the vision confound. Moot for figures regardless: **all 265 labeled figure/diagram records are already in master** (the DocVQA `validation` split has exactly 265; the cached `test` split is unlabeled) — none left to mine without the external DocVQA train set.

**Tesseract literature backdrop** (to cite properly later): a peer-reviewed OCR benchmark (_Journal of Computational Social Science_, ~18,568 documents) finds Tesseract competitive on clean single-column print but substantially worse than commercial/cloud OCR on noisy or structurally complex documents, losing layout structure on tables/figures — context for the abstain population as an OCR-ceiling artifact. NB: the **figure/diagram-specific localization skew above is our own measurement**, not from that literature. _(Full citation TBD.)_

### Verification (2026-06-28)

Manual spot-checks against the raw `ocr_menu` (CPU; no re-scoring of the scorer).

- **Localizer / abstain labels verified.** Inspected the OCR menus for 6 figure/diagram abstains (43130, 43133, 51212, 64731, 64983, 64984): the gold answer is genuinely **absent from each menu — no localizer glitch.** Tesseract captured axis labels/titles but never the data values / node text the questions targeted (e.g. the only "0" in 43130 is inside a Bates id; the flowchart node OCR'd as garbled fragments).
- **found_answer matcher is exact** (`_norm` = NFC + quote-fold + casefold + whitespace-collapse) — it does **not** tolerate punctuation / spelling / canonicalization differences. Hand-inspecting a sample of the 60 answerable errors (ck-1284), many are **scorer artifacts, not model misreads**: trailing punctuation; **gold-label typo** (rec 1795 — gold "calender", OCR + model "calendar"; the model read correctly, the gold is wrong); **gold canonicalization** (rec 822/824 — document + model say "Federal Food and Drug Administration", gold drops "Federal"); **different document element** (rec 59845 — model read the typed date present in OCR, gold wanted the received-stamp date not in the menu).
- **Implication:** the reported answerable found_answer accuracy **0.915 is a conservative floor** — true perception accuracy is higher. (Not re-scored across all 60 errors, so no exact corrected number is claimed.) Genuinely vision-hard failures remain isolated to the **figure/diagram misreads** (real chart misreads, gold correctly un-citable).
